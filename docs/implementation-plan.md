# План реалізації та протокол виконання задач (v1.0.0)

## 1. Загальний огляд

У межах ЛР №4 реалізовано першу повнофункціональну версію системи «Облік енергоресурсів ОСББ» (v1.0.0) за погодженим планом розроблення.
Усі робочі дані зберігаються в пам'яті сервера (`InMemoryEnergyStore`) протягом його роботи. Для забезпечення потокобезпеки операції читання й запису захищені блокуванням `lock`.

## 3. Детальний перебіг робіт та рецензування

### 3.1. Реалізація UC-01 (Ткаченко Богдан)
- **Зміни:** створено клас `ReadingRules` з методами `ValidValue`, `ValidCoefficient`, `CanAccept`. У сервісі `EnergyService` додано обробник `SubmitReading` з перевіркою хронології та незменшення значень.
- **Перевірка (Трофименко Арсеній):** перевірено, що при спробі передачі меншого значення повертається 409 `lower_value`, а при ранішому часі — 409 `invalid_date`. Історія лічильника при цьому залишається без змін.

### 3.2. Реалізація UC-02 та UC-03 (Трофименко Арсеній)
- **Зміни:** реалізовано маршрути `POST /api/meters` та `POST /api/meters/{id}/decommission`. Створено обробку статусів `Active` та `Decommissioned`.
- **Перевірка (Ткаченко Богдан):** протестовано валідацію вхідних полів (порожній номер або від'ємний коефіцієнт повертають 400 Bad Request). Перевірено блокування внесення показників для виведеного лічильника.

### 3.3. Реалізація UC-04 та UC-05 (Трофименко Арсеній)
- **Зміни:** реалізовано фільтрацію та впорядкування історії показників, а також метод обчислення споживання `CalculateConsumption` із урахуванням тарифного коефіцієнта.
- **Перевірка (Ткаченко Богдан):** протестовано на контрольних даних: показники 1200 та 1260 з коефіцієнтом 1.5 дали точний результат 90.0 кВт·год.

### 3.4. Клієнтський застосунок `Labka.Client`
- Розроблено автономну консольну програму на .NET 8.0, яка взаємодіє з сервером через HTTP/JSON.
- Реалізовано повне меню користувача (пункти 1–6) та функцію автономної демонстрації всіх погоджених сценаріїв (пункт 7).
