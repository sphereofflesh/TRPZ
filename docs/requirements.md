# SRS v1.0 / Базова лінія вимог

## 1. Контекст системи

Система призначена для обліку та контролю показників енергоресурсів у багатоквартирному будинку або ОСББ. Підприємство має вести облік лічильників, фіксувати показники, переглядати історію, а також розраховувати споживання за обраний період.

## 2. Функціональні вимоги

| ID | Опис вимоги | Критерій приймання |
| --- | --- | --- |
| FR-01 | Система повинна дозволяти оператору обліку вносити показник лічильника. | Після введення коректного значення, дати та часу показник зберігається у системі та відображається у історії. |
| FR-02 | Система повинна дозволяти зареєструвати новий лічильник. | Після введення серійного номера, типу, місця встановлення та дати встановлення лічильник стає доступним для внесення показників. |
| FR-03 | Система повинна дозволяти виводити лічильник з експлуатації. | Після переведення лічильника в стан «Виведено з експлуатації» він більше не приймає нові показники. |
| FR-04 | Система повинна надавати історію показників для обраного лічильника. | Користувач бачить список показників у порядку зростання часу, із датою, часом і значенням. |
| FR-05 | Система повинна обчислювати споживання енергоресурсу за обраний період. | Для активного лічильника система розраховує різницю між двома вибраними значеннями і показує результат. |

## 3. Нефункціональні вимоги

| ID | Вимога | Критерій приймання |
| --- | --- | --- |
| NFR-01 | Час відправки/обробки даних для внесення показника не повинен перевищувати 2 секунди у 95 % запитів у навчальному середовищі. | Для стандартного сценарію внесення показника відповідь отримана за 2 с або менше у 95 % випадків. |
| NFR-02 | Система повинна валідувати значення показника перед збереженням. | Якщо значення менше або дорівнює попередньому для цього лічильника, система відхиляє запис і показує повідомлення про помилку. |
| NFR-03 | Доступ до функцій системи повинен бути розмежований за ролями. | Оператор обліку має доступ до введення й реєстрації лічильників, а енергоменеджер — до перегляду історії та розрахунку споживання. |

## 4. Базова лінія вимог

Поточна базова лінія v1.0 включає п’ять основних сценаріїв: реєстрація лічильника, внесення показника, виведення з експлуатації, перегляд історії, розрахунок споживання. Подальші зміни вимог після фіксації baseline потрібно документувати окремо й оцінювати вплив на уже погоджені сценарії.

## 5. Ключові прийняті припущення

- Один лічильник відповідає одному типу ресурсу (електрика, газ, вода).
- Для визначення споживання використовується різниця між послідовними показниками.
- Система не враховує автоматичну синхронізацію з фізичними пристроями на етапі v1.0.
